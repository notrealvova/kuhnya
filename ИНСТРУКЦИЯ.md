# Кухня на двоих — запуск без Claude

Займёт около 30 минут один раз. Всё бесплатно. Делать с компьютера, с включённым VPN.

Что внутри папки:
- `index.html` — само приложение;
- `config.js` — сюда вставляются настройки вашей базы (шаг 1.6);
- `vendor/` — библиотека Firebase, не трогать;
- `manifest.json`, `icon-*.png` — значок и название для экрана телефона;
- `firestore.rules` — правила доступа к базе (шаг 1.5).

---

## 1. База (Firebase)

1. Зайдите на **console.firebase.google.com** под Google-аккаунтом → **Create a project** (Создать проект). Название любое, например `kuhnya`. Google Analytics можно выключить.
2. В меню слева: **Build → Authentication → Get started**. На вкладке **Sign-in method** включите **Email/Password** (только первый переключатель) → Save.
3. Там же вкладка **Users → Add user**. Создайте двух пользователей: почта и пароль Вовы, почта и пароль Кристины. Почта может быть любая настоящая, письма не придут — это просто логин.
4. В меню слева: **Build → Firestore Database → Create database**. Регион — любой европейский (например `eur3` или `europe-west`). Режим — **Production mode**.
5. В Firestore откройте вкладку **Rules**, сотрите всё и вставьте текст из файла `firestore.rules`. Впишите в квадратные скобки ваши две почты из шага 3 → **Publish**. Так в базу пустит только вас двоих.
6. Шестерёнка слева сверху → **Project settings** → внизу блок **Your apps** → кнопка **</>** (Web). Название любое, галочку Hosting НЕ ставить → Register app. Появится код с `const firebaseConfig = { apiKey: "...", ... }`. Скопируйте всё, что между фигурными скобками `{ }` — понадобится на шаге 2.4.

## 2. Сайт (GitHub Pages)

1. Зарегистрируйтесь на **github.com** (если ещё нет).
2. Справа сверху **+ → New repository**. Название `kuhnya`, тип **Public**, остальное не трогать → **Create repository**.
3. На странице пустого репозитория нажмите ссылку **uploading an existing file**. Перетащите в окно **всё содержимое** распакованной папки (файлы и папку `vendor` целиком) → внизу **Commit changes**.
4. Откройте в репозитории файл `config.js` → значок карандаша (Edit). Замените всё между `{` и `}` на скопированное из Firebase на шаге 1.6 → **Commit changes**.
5. Вкладка **Settings → Pages**. В разделе Build and deployment: Source — **Deploy from a branch**, Branch — **main**, папка **/ (root)** → **Save**.
6. Подождите 1–2 минуты и обновите страницу. Сверху появится ссылка вида `https://ВАШ-ЛОГИН.github.io/kuhnya/` — это и есть приложение.
7. (Для надёжности) В Firebase: **Authentication → Settings → Authorized domains → Add domain** → `ВАШ-ЛОГИН.github.io`.

## 3. Телефоны

Откройте ссылку на каждом телефоне и войдите своей почтой и паролем.
- **iPhone (Safari):** кнопка «Поделиться» → «На экран „Домой“».
- **Android (Chrome):** ⋮ → «Добавить на главный экран» / «Установить приложение».

Дальше открываете с иконки, как обычное приложение. Вход запоминается.

## 4. Перенос данных из Claude

1. В старом приложении в Claude: ⚙ → **Выгрузить всё** → «Скачать файл» (или «Скопировать текст»).
2. В новом: ⚙ → **Загрузить** → выбрать файл (или вставить текст) → «Загрузить».

Достаточно сделать один раз с одного телефона — у второго всё появится само.

## 5. Как обновлять приложение

Данные (планы, покупки, дневник, рецепты) обновляются сами и сразу видны обоим — ничего делать не нужно.

Если появится новая версия приложения (новые функции, блюда):
1. В репозитории на GitHub: **Add file → Upload files** → перетащить новый `index.html` → **Commit changes**.
2. Через 1–2 минуты обновится у обоих. `config.js` при этом не трогать — настройки базы останутся.

## Если что-то не так

- **«Нет связи с Firebase»** — включите VPN.
- **«Неверная почта или пароль»** — проверьте пользователя в Firebase → Authentication → Users. Пароль можно сменить там же (⋮ → Reset password не сработает без почты, проще удалить пользователя и создать заново — данные не пропадут).
- **«Нет доступа к базе»** — почта не вписана в правила (шаг 1.5) или вписана с опечаткой.
- **«Не заполнен config.js»** — шаг 2.4.
- **Ссылка показывает 404** — подождите пару минут после шага 2.5; проверьте, что `index.html` лежит в корне репозитория, а не во вложенной папке.
